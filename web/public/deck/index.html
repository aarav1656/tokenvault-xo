The Story of TokenVault on XO

foldingcash/smart-contracts ships TokenVault in CashScript: a covenant that releases fungible CashTokens by block height while the reward halves every period. Each release needed a JavaScript script to compute the next state. We migrated it to an XO template. The two original contracts are embedded unchanged, and the template itself computes the halving schedule and the next state NFT commitment. Every transaction is an XO invitation that blaze.xo.cash inspects.

Benefits of TokenVault on XO

  1. The template computes the halving schedule and the next state commitment, no side script
  2. Original TokenVault_Mint and TokenVault_Release bodies embedded, addresses equal the CashScript SDK
  3. Seven actions with follow-ups: fundMint, mint, prepareFeeCoin, release, finalRelease, reclaim, sweep
  4. Open any transaction in blaze.xo.cash as an invitation, template id 833cf84d9673...
  5. 54 tests on the BCH 2026 VM, each guard has a negative test that names the rejecting contract line
  6. MUTANT=commitment, signer, payout or locktime switches one guard off and the tests turn red

BCH Usage

Fungible CashTokens sit in a P2SH32 covenant next to a state NFT, and every release is bound to block height by its locktime. Chipnet lifecycle, vault of 60 tokens: 4 releases, locked 60, released 60, read back from Electrum by scripts/verify.mjs.
