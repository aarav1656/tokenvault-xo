tokens that pay out by the block

TokenVault locks fungible CashTokens in a covenant beside a state NFT. The fund releases up to the current block height, the reward halves every period, and the XO template computes the next state. Every move is an XO invitation that blaze.xo.cash opens.

every step is an invitation

A row is one transaction of the vault's life, in order. Its invitation file holds the signed commits that built it. The template file holds the scripts. blaze.xo.cash rebuilds the transaction from the two.

  1. 1

    Import Template

    Copy the template JSON. In blaze.xo.cash choose Import Template and paste it.

  2. 2

    Join Invitation

    Copy any invitation JSON from the table. Choose Join Invitation and paste it. blaze lists the inputs, the outputs and the state NFT.

  3. 3

    Inspect Transaction

    Or paste a txid into Inspect Transaction to see the same transaction as the chain holds it.

the chain agrees

Your browser opens a WebSocket to a public Electrum server, asks for every raw transaction and its merkle proof, decodes the bytes with libauth and re-checks the vault's rules. The invitation files supply the txids and the vault's constructor arguments. Every amount and state below comes from the chain.

the template does the math

Four inputs. Every amount, halving test and next state NFT in the table is evaluated by the template's own scripts (releaseAmount, halvingNow, nextStateHex) with compileCashAssemblyString in this page, the call the XO engine makes. The page chooses only the block height each release runs to: the end of the current halving period.

migrated, not rewritten

The two CashScript contracts are embedded unchanged, so every vault address equals the CashScript build for the same arguments. XO adds the actions, the roles and the arithmetic that writes the next state NFT.
